# SurviveOs：搭建一套自己可维护可生长的乡野生存系统

## 一、项目是什么

SurviveOs 不是一次性装修项目，而是一套长期迭代的"基地操作系统"：一个乡野基地（暖村木屋 + 地堡 + 阁楼间 + 阁楼仓库 + 庭院 + 草地 + 钓台 共 7 个物理区域），每个区域下拆成若干功能子模块（照明、控温控湿、灌溉、影音、储能……），子模块数量会随着想法增加而持续生长，所以需要一套**可复用的设计方法论**，而不是每次从零开始想格式。

这份文档（0001）定义方法论；《0002-区域与子模块清单》定义范围和进度；《0003-项目部署与组织规划》定义文档目录/对话/编号怎么组织。三份文档都在 `00-总览/` 文件夹里，是所有子模块对话开始前都应该先读的上下文。

## 二、总体难度与施工分工原则（全局约束，所有子模块默认遵循）

- **约 80% 的工作量按"自己动手可完成"来设计**：选型、走线、安装、调试优先给出普通人在家能操作的方案，不因为省事就默认找师傅。
- **只有真正有危险隐患或需要专业资质的部分才找工人**：例如涉及高压/强电改造、燃气、结构承重开洞、防水层破坏后的专业修复、化粪池/污水提升泵等给排水专业施工。每个子模块在"方案原理推演"阶段的施工纲要里，需要明确标出"自己动手"还是"需要找工人"，并说明找工人的原因（危险/资质/精度要求），不能笼统一句"建议专业施工"了事。
- **器件选型必须是中国大陆主流电商平台或二手平台能买到的主流商品**：新品优先淘宝、天猫、京东、1688；二手优先闲鱼。不选海外代购、进口小众品牌或需要特殊渠道才能买到的器件，除非该子模块的对话里用户明确要求。选型阶段给出的每一件硬件都应该是搜索关键词就能在这些平台直接找到、多店铺可比价的"能实际买到"的东西，而不是理论上存在但国内不好买的型号。

## 三、三段式工作流（每个子模块都要走这三步）

项目整体分三大部分，但**不是"先把所有子模块做完第一部分，再统一做第二部分"**，而是**每个子模块自己走完这三步**，三步做完这个子模块才算完整交付：

### 阶段 1 · 方案原理推演

回答"为什么这样做、做成什么样"。产出一份结构化方案文档，从已完成的 3 个子系统（模拟阳光 / 卫生间灯箱 / 稀树草原浇灌）提炼出的标准骨架：

1. **结论先行**：一段话说清系统是什么、解决什么问题
2. **核心目标 / 硬性约束 / 已有条件**：目标可以有取舍优先级，约束是不可谈判的边界（比如"必须接入华为智慧生活"），已有条件是可复用的现状（已买的设备、已有的结构）
3. **设计理念**：关键选择为什么这样定，及被放弃的替代方案（例如"为什么地埋滴灌而不是喷灌"）
4. **系统总体架构**：分层描述（例如水源层/控制层/管网层，或光学层/结构层/控制层），画出层与层之间怎么联动
5. **分区/子系统详细设计**：每个分支给出规格参数表
6. **智能生态联动**：与华为智慧生活 App / HomeAssistant / ESPHome 的对接方式和自动化逻辑（本项目已确立"App 管想不想、本地传感器管该不该"的双钥匙模式，新模块默认沿用）
7. **成本核算**：一次性部署成本 + 每年使用成本，给出可压缩的地方
8. **施工纲要**：主要工序顺序，并按"二、总体难度与施工分工原则"标出每道工序是自己动手还是找工人
9. **风险**：会出问题的地方，以及兜底方案
10. **决策点**：需要用户拍板的分叉选项，明确列出，不替用户擅自决定

### 阶段 2 · 设备电商平台选型

回答"买什么、去哪买、多少钱"。产出一个**专题库**：每个要采购的硬件单独一张卡片，包含：

- 拆解原理图（等轴测爆炸图或结构示意）
- 作用原理（一两句话讲清这个部件在系统里干什么）
- 关键参数表
- 淘宝 / 闲鱼搜索直达链接 + 价格区间（新品淘宝/1688/京东价 vs 闲鱼二手价分开标，全部限定在大陆主流平台能买到的商品）
- 上一件 / 下一件连续翻阅导航
- 一个汇总索引页，按子系统分组，标出总预算区间

价格标注今天的日期区间即可，采购前需要在对应对话里让 Claude 用 WebSearch 复核实时价格和链接是否失效。

### 阶段 3 · 施工

回答"怎么装、按什么顺序装、装的时候要注意什么"。产出：

- 完整 BOM 采购清单（汇总阶段 2 的选型结果，含数量、单价、链接）
- 代码/配置文件（ESPHome yaml、HomeAssistant automations/configuration、控制脚本等，若子模块涉及自动化）
- 3D 打印文件（STL + OpenSCAD 源文件，若子模块涉及定制结构件）
- 部署 / 施工步骤（按工序先后，逐条标注"自己动手"还是"需要师傅"及理由）
- 开发优先级表（P0 必须先做 / P1 核心功能 / P2 体验优化 / P3 锦上添花）
- 关键注意事项（安全、防冻、承重、走线等踩坑提醒）

## 四、输出载体的两种形式

三段式内容目前观察到两种承载形式，按内容体量选：

- **单页 HTML 方案页**：适合方案推演+施工纲要合并展示的场景，用锚点导航串起目标/理念/架构/分区/成本/施工/风险/决策点，适合要给自己反复翻阅、也可能给包工头/家人看的场景。
- **README.md + 代码/STL 资产目录**：适合偏工程实现的子模块（涉及 ESPHome/HomeAssistant 代码、3D 打印文件），文档负责讲清楚"为什么"和"怎么部署"，代码文件本身是可执行产物。

两种形式不冲突，可以在同一个子模块里搭配用（例如方案页用 HTML，配套代码单独归档）。具体某个子模块用哪种、发布在哪里，见《0003-项目部署与组织规划》。

## 六、如何推进一个新子模块的对话

1. 新开一个对话，说明要做哪个区域的哪个子模块（例如"设计 0203 控温控湿"或"设计地堡的控温控湿模块"）
2. Claude 应先读 `00-总览/` 文件夹里的《0001-总览与方法论》《0002-区域与子模块清单》《0003-项目部署与组织规划》三份项目文档，确认该子模块的状态、编号、是否有可复用的旧素材、以及是否与其他子模块有联动关系（例如 0211 全屋中枢会和几乎所有智能模块产生数据联动，做的时候要留意）
3. 按三段式依次推进：方案原理推演 → 设备电商平台选型 → 施工；每段做完更新一次《0002-区域与子模块清单》里对应模块的状态，并按《0003-项目部署与组织规划》的目录/编号规范写回项目文档
4. 涉及价格、链接、型号的内容，做之前用 WebSearch 核实一遍是否还有效、是否有更优选项、是否为大陆主流平台可买到的商品

## 七、跨模块的共识（新模块默认遵循，除非该子模块的对话里明确要改）

- 智能家居生态：以华为智慧生活 App 为统一控制入口，本地传感器/逻辑走 ESPHome + HomeAssistant，双钥匙串联（App 决定要不要、本地判断该不该）
- 采购渠道：淘宝/天猫/京东/1688 新品比价，闲鱼二手比价，只选大陆主流平台能买到的主流商品
- 施工原则：约 80% 自己动手，只有危险隐患或专业资质要求的部分找工人，且需说明理由
- 地域气候：需要考虑冬季防冻（草地灌溉方案已确认为北京气候设计，其余模块所在地域如与此不同，需要在对应对话里重新确认）
