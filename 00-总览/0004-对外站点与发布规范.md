# 对外站点与发布规范

回答"怎么让家人朋友能持续看到项目进展、并且不用你手动一次次做网页"。这份文档定义对外站点（下称"总站"）的信息架构、更新机制、以及每个模块对话收尾时要多做的那一步。

## 一、目标与受众

给家人朋友看的，不是做给陌生人看的——用来同步进展、收集意见、方便磋商，不是营销页面。

**2026-09-15 更新**：仓库 `richardvane-droid/SurviveOs` 是 public，由它生成的总站也就是公开可访问的（靠不公布链接来控制传播范围，不是靠权限）。站点页面都带 `noindex` 且有 `robots.txt`，不主动让搜索引擎收录，但**不要当成私密页面**——真正私密的东西（地址、家人信息、证件、账单）只放 Google Drive，仓库和站点里都不写。

## 二、发布载体：GitHub Pages（2026-09-15 改定）

原方案是用 Claude 的 Artifact 发布总站，实际落地时改成了 GitHub Pages，原因：

- **自动更新**：总站内容是从仓库现有文档生成的（第四节），放在同一个仓库里，push 完 GitHub Actions 直接重建发布，不需要谁记得去"重新发布一次"
- **纯手机可维护**：不需要任何电脑参与——手机上让云端会话改完文件 push，站点几分钟后自己就更新了；要手动重建，在 Actions 页点一下 Run workflow
- **固定网址**：https://richardvane-droid.github.io/SurviveOs/ ，不会变，家人朋友收藏一次就够
- 代价是没有 Artifact 自带的评论区（见第六节），以及站点跟仓库一样是公开的（见第一节）

具体机制：

| 东西 | 位置 |
| --- | --- |
| 生成器 | `tools/build_site.py`（只用标准库，读仓库内容写 `docs/`） |
| 自动发布 | `.github/workflows/pages.yml`（push 到 master 或手动触发） |
| 生成结果 | `docs/`，已在 `.gitignore` 里——每次由 CI 重新生成，不进版本库 |

生成器做四件事：读 `0002-区域与子模块清单` 算进度与状态徽章、把每个模块文件夹里的 `.md` 渲染成网页、把已有的单页 HTML 方案文档原样搬过去（这是手机上看方案的唯一途径，GitHub 网页端打开 `.html` 只会显示源码）、读 git 提交历史生成"最新动态"时间线。

## 三、总站信息架构

总站是单页 + 锚点导航（不做多路由应用），内容分四块：

1. **首页仪表盘**：项目一句话介绍 + 区域导航 + 整体进度统计（✅/🚧/🆕/⬜ 四档计数 + 进度条），数字由生成器从 0002 清单实时算出，不手写
2. **区域板块**（9 个区域各一个分栏：01~07 物理区域 + 08 虚拟空间 + 09 设想）：区域说明 + 模块卡片（状态徽章 + 编号 + 名称 + 清单里的说明 + 该模块文件夹内所有文档的入口）
3. **最新动态时间线**：直接取 git 提交历史（日期 + commit 说明），倒序展示——commit message 写清楚了，时间线就是对的，不用另外维护一份更新日志
4. **元文档入口**：`00-总览/` 那几份（方法论、清单、部署规划、发布规范、启动清单、户型图、对照表）

## 四、数据来源与一致性原则：总站是"生成的视图"，不是"另一份存档"

- 每个模块的方案/选型内容，唯一权威来源现在是 GitHub 仓库 `richardvane-droid/SurviveOs` 对应模块文件夹里的文件（详见《0003-项目部署与组织规划》第〇节）
- 总站的区域板块、进度统计、时间线，都是从仓库这些文档现有内容**汇总生成**出来的，不单独维护一份"总站专用"的内容库——每次重新生成总站，就是重新读一遍仓库里的 0002 清单和各模块 README，按当前状态重新拼一次首页/区域板块/时间线，然后整页重新发布
- 好处：不会出现"总站说完成了，但模块文档说还没做完"这种双份记录对不上的情况——只要仓库更新了，总站下一次重新生成就会自动带出最新状态

## 五、更新机制：两层触发，不需要你手动维护网站

### 主触发：push 即重建，不用记着做这一步

延续《0003-项目部署与组织规划》第六节的收尾纪律（把模块对话产出落到仓库 + 更新 0002 清单）即可，**不需要再额外做"重新发布总站"这一步**——push 到 master 之后 GitHub Actions 自动重建，几分钟内生效。

这跟原来设计的"维护时顺手重新生成"相比，少了一个会忘的人工环节：只要内容进了仓库，站点就一定跟得上；反过来说，没 push 的改动站点上也就看不到。

### 兜底：定期维护检查（防止漏更新）

自动构建之后，原本设想的"定时任务比对差异"就不需要了。真正要兜底的变成两件事：一是 Actions 有没有跑失败（失败会在仓库 Actions 页标红，GitHub App 也会推通知），二是有没有改完忘记 push。定期维护对话里顺带看一眼即可。

## 六、权限与分享方式

- 站点跟仓库一样是**公开**的，靠"不主动公布链接"控制传播范围：微信把 https://richardvane-droid.github.io/SurviveOs/ 发给谁，谁就能看
- 页面带 `noindex` + `robots.txt`，不主动让搜索引擎收录，但这不是权限控制（见第一节的提醒）
- **没有评论区**——这是换成 Pages 的代价。家人朋友的意见目前走微信，你觉得值得留痕的，让会话记进对应模块的 README.md「关键决策记录」里
- 以后如果确实需要评论/投票/访客身份，再单独评估用 Artifact 做一个补充页面，不必为此把整个总站搬回去

## 七、和现有文档的关系

- 《0003-项目部署与组织规划》第六节"对话怎么开、怎么收尾"里的维护流程**不需要**再追加发布动作，push 完自动重建，见本文档第五节
- 总站网址见本文档末尾

## 八、首版视觉草稿画布（2026-09-03）

在正式的总站（第三节信息架构）搭建之前，先用 **Claude Design 画布工具**做了一版可视化草稿，作为总站视觉方向的参考，不是第三节定义的正式总站本身——两者机制不同，先说明区别：

- **载体不同**：草稿画布是一个多画板（artboard）的 Claude Design 画布，发布形态也是 Artifact，但内部用的是画布编辑器（可点选/拖拽调整每个元素），不是第三节说的"单页锚点导航 HTML"；正式总站仍应按第三节的信息架构、用普通 Artifact 单页搭建。
- **链接方式不同**：草稿画布里 5 个已完成模块（0201/0202/0601~0603）是画布内的详情画板，用画布内的空间布局区分，并不是跳转到各模块各自独立发布的 Artifact——这一点和第四节"总站只做索引、跳转到模块自己的页面"的原则不完全一致，正式总站上线时仍需按第四节的方式做真正的跳转索引。
- **内容范围**：草稿画布覆盖了首页总览（7 区域 + 39 模块统计）、7 个区域的模块骨架卡片（34 个待设计模块占位、5 个已完成模块的详情卡片），但没有做第三节里的"最新动态时间线"和"留言区入口"两块，也没有接入 0002 清单的自动生成逻辑（是手工提炼当前状态做的一次性快照，不会随 0002 更新自动变化）。

**草稿画布网址**：https://claude.ai/code/artifact/0570beac-3b86-4c51-9bdf-9f1f389171b3

后续设计到某个新模块、或已完成模块状态更新时，如果想让草稿画布保持同步，需要专门开一次对话用 Claude Design 重新编辑对应画板并重新发布——这不会自动发生，也不属于本文档第五节定义的"总站自动更新机制"（那套机制是为正式总站设计的）。

**总站网址**：https://richardvane-droid.github.io/SurviveOs/ （2026-09-15 接上 GitHub Actions 自动发布；首次发布要等这套改动合进 master、Actions 跑完一次）
