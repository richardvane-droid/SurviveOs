# SurviveOs

搭建一套自己可维护可生长的乡野生存系统——本仓库是这套项目文档和交付物的**正式存放位置**，2026-09-03 从 claude.ai Project 知识库迁移而来。

## 这个仓库解决什么问题

之前所有文档都存在 claude.ai 的 SurviveOs Project 知识库里，靠 39 个各自独立的模块对话在结束时用 `project_write` 写回。这套机制有个结构性问题：`project_write` 是整份覆盖，不是增量合并，也没有版本冲突检测——如果两个模块对话前后脚都改了同一份共享文档（比如 `0002-区域与子模块清单.md`），后写的会静默覆盖先写的，不会报错提醒。0601 那次"无法自动写入"就是撞上了类似情况。

改用本地 git 仓库之后：

- 每次改动是一次 `git commit`，有完整历史和 diff，出问题能看清是哪次改的
- 真出现冲突，git 会明确提示冲突要你处理，而不是悄悄丢数据
- 不再依赖 claude.ai 对话里 Projects 工具的写入判断和权限逻辑，写入本身更可靠

## 目录结构

和 claude.ai Project 里原来的编号规则完全一致（详见 `00-总览/0003-项目部署与组织规划.md` 第三、四节）：

```
00-总览/          方法论、清单、部署规划、发布规范、对话启动清单（0001~0005）
01-暖村木屋/       7 个模块，均未开始
02-地堡/           含已完成的 0201 模拟阳光、0202 卫生间灯箱系统
03-阁楼间/ 04-阁楼仓库/ 05-庭院/   均未开始
06-草地/           含已完成的 0601~0603 稀树草原环境系统（共用一套方案）
07-钓台/           唯一还没做范围拆解的区域
```

已完成三阶段的模块是**文件夹**（README/方案文档 + code/ + stl/ + 采购清单等资产）；未开始或只有轻量索引的模块是**单个 `.md` 文件**。某个模块从零推进到有实质产出时，把对应的 `.md` 换成同名文件夹。

## 日常怎么用

**设计讨论还是在 claude.ai 的 SurviveOs 项目里进行**——39 个模块各自的对话、以及以后新开的对话，都还在那边，这一点不变。变的只是"讨论完之后内容写到哪"：

1. 在某个模块的 claude.ai 对话里把方案/选型/施工内容聊定
2. 把这次对话的产出（文本内容、代码、STL、BOM 等）带到本地维护环节，有两种做法：
   - **在云端 Cowork 会话里**：跟会话说"帮我把刚才 0203 对话里定的方案写进本地仓库"，用 Bash/Read/Write/Edit 改文件、`git commit`，需要的话再 `git push`
   - **在你 Mac 本地用 Claude Code CLI**：`cd ~/Projects/SurviveOs`，把对话产出贴给本地的 Claude Code，让它改文件、`git commit`
3. 顺手更新 `00-总览/0002-区域与子模块清单.md` 里对应条目的状态
4. 如果状态跨了一档（⬜→🚧、🚧→✅），按 `00-总览/0004-对外站点与发布规范.md` 重新生成总站/画布

`00-总览/` 这几份文档在 claude.ai Project 里还留着一份同步副本，方便新开模块对话时直接读到背景（claude.ai 对话没法直接读你电脑上的这个仓库）；但权威版本以本仓库为准，改完本地记得找时间把关键改动同步贴回 claude.ai 那边，避免两边长期不一致。

## GitHub 备份

本仓库已 `git init` 并完成首次 commit，尚未关联远程仓库。备份到 GitHub：

```bash
gh auth login          # 如果还没登录过
gh repo create SurviveOs --private --source=. --remote=origin --push
```

之后每次改动 `git add -A && git commit -m "说明"`，定期 `git push` 即可。
