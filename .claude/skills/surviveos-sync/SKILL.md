# SurviveOs 模块产出同步

背景：权威文档层是 GitHub 仓库 `richardvane-droid/SurviveOs`（公开），**不绑定任何一台电脑**——手机上开个云端会话就能改。claude.ai Project 知识库那边只是同步副本，写入不可靠，历史上出过静默覆盖。结构与边界口径以仓库根目录 `CLAUDE.md` 为准，本文件只讲"怎么落地这一次产出"。

## 前置检查

1. 确认工作区里有这个仓库：`git -C <工作区路径> rev-parse HEAD`。没有就先挂上（`add_repo` + `git clone`），不要假装完成。
2. 如果用户只说了编号（"同步 0203"）却没给内容，**先问他要同步什么**，不要凭空编造。紧接在某次模块设计之后说"同步一下"，产出就是刚才对话里生成的内容。

## 目标路径：一个模块 = 一个文件夹 = 一个 README.md

四位编号前两位是区域：01 暖村木屋 / 02 地堡 / 03 阁楼间 / 04 阁楼仓库 / 05 庭院 / 06 草地 / 07 钓台 / 08 虚拟空间 / 09 设想（00 是总览元文档，不是模块）。

**44 个模块的文件夹和骨架 README.md 已经全部建好了**，直接往 `NN-区域/四位编号-模块名/README.md` 里写，不要新建 `.md` 文件，也不要改文件夹名（文件夹名和 Drive 素材库逐字对应，改名等于切断两库的纽带）。找不到对应文件夹时先 `ls` 确认编号，别猜。

例外：0601~0603 三个模块共用 `06-草地/0601-0603-稀树草原环境系统/`。

代码、STL、单页 HTML 方案文档放同一文件夹的 `code/`、`stl/`、`images/` 子目录，README.md 负责索引它们。

## 写入方式

**先读一遍目标 README.md 当前内容再改**，把新产出合并进去，保留已有的「关键决策记录」等历史信息和底部的「## 素材」段，不要整段覆盖。骨架 README 的结构是：

```
编号 / 状态 / 最近更新
# 编号 名称
## 方案原理推演
## 设备电商平台选型
## 施工
## 关键决策记录
## 预算摘要
## 素材        ← Drive 路径，不要删
```

状态从 ⬜ 变 🚧、或 🚧 变 ✅（或三阶段里新完成一个）时，同步改 `00-总览/0002-区域与子模块清单.md` 里对应那行的图标和说明。

## 素材归 Drive，不进 git

施工照片、说明书 PDF、商品页截图、手绘草图拍照、视频一律放 Google Drive 的 `SurviveOs-素材/<区域目录>/<四位编号-模块名>/` 下三个子文件夹（`施工照片/`、`说明书与保修卡/`、`商品页截图/`），仓库里只在 README 的「## 素材」段登记一行说明。对照表见 `00-总览/0009-仓库与Drive素材对照表.md`。

## 收尾

1. `git add -A && git commit -m "<编号> <模块名>：<一句话说清改了什么>"`
2. **`git push` 是默认动作，不是可选项**——总站靠 push 触发 GitHub Actions 重建，不推就等于没更新。
3. **不需要手动发布总站**：push 到 master 后 `.github/workflows/pages.yml` 自动重建 https://richardvane-droid.github.io/SurviveOs/ ，几分钟生效。别再按旧文档去"重新生成总站/画布"。
4. 可选：如果这次改到了 `00-总览/` 下的文件，问用户要不要把内容也贴回 claude.ai Project 保持同步。不问就别自动做。

## 汇报

简洁说清楚：改了哪些文件、0002 状态有没有变、commit 和 push 有没有成功、站点会不会重建。不要长篇复述内容本身，用户自己知道刚才聊了什么。
