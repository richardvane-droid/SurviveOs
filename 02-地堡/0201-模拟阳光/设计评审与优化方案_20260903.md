# 0201 模拟阳光 — 设计评审与优化方案

## 一、结论先行

原方案（南光 FS-300B + FL-20G 菲涅尔透镜 + 3.5m 电动滑轨 + 双轴电动云台，HomeAssistant + 华为智慧生活四场景联动）在**灯光效果设计**和**场景参数**层面是扎实的，但在**机械结构完整性、控制安全性、代码可靠性、文档一致性**四个维度存在实质缺口，其中"双轴云台机械结构从未被设计"和"蓝牙控制协议疑似编造"这两点如果不解决，整个方案会在施工阶段卡死。本次评审不推翻原方案的灯光逻辑和场景设计，只修复上述缺口，并把两份互相矛盾的采购清单合并成一份权威版本。

## 二、问题分级

### A 级（必须修复，否则无法施工或有安全隐患）

| # | 问题 | 影响 |
|---|---|---|
| A1 | 双轴云台机械结构未设计 | 现有 STL/OpenSCAD 只做了菲涅尔调焦齿轮和滑轨转接板，云台本体（俯仰轴/旋转轴壳体、减速机构、轴承位）完全空白，`esphome_gimbal.yaml` 里的减速比是"假设"值，无对应物理实现 |
| A2 | 步进电机开环控制，无回零、无限位保护 | 3.5m 长行程+悬挂重物，丢步后系统不自知，也没有物理限位阻止滑块冲出轨道两端 |
| A3 | 物理急停按钮未接入 ESPHome | 采购了但代码里没有对应 GPIO，无法真正断电 |
| A4 | `fs300b_control.py` 协议疑似编造 | mesh key、UUID 都是示例值，很可能连不上灯，需要重新验证再动手 |
| A5 | 顶棚开孔/强电接线的"自己动手 vs 找工人"未标注 | 违反 0001 方法论强制要求，且重物过顶悬挂，安全边界不能含糊 |

### B 级（影响体验/后续维护，建议一并修复）

| # | 问题 |
|---|---|
| B1 | 两份采购清单互相矛盾（¥1958 vs ¥2314.7），需要合并 |
| B2 | 买了但代码里没用的硬件：限位开关、温度传感器、光照传感器、mmWave人体传感器、OLED、编码器 |
| B3 | 双钥匙模式（App 管想不想/本地传感器管该不该）没有落地，四场景全部纯手动/定时 |
| B4 | 重量/扭矩/推力未做计算校验，膨胀螺栓选型缺依据 |
| B5 | 场景定时触发不完整，只有场景1配了 time trigger |
| B6 | HA 主机选型前后矛盾（树莓派5 vs 斐讯N1），影响未来 0211 中枢扩展能力 |

## 三、A 级问题的优化设计

### A1 · 双轴云台机械结构补设计

**设计理念**：不做自制蜗轮蜗杆（加工精度要求高、自制风险大），改为"外购成品云台底座 + 自制转接结构"的组合方案，把机械风险转移到成熟工业品上。

- 俯仰轴：外购小型电动云台/摄影摇臂云台的俯仰模组（这类产品在淘宝有大量现货，通常自带蜗轮蜗杆减速和步进/伺服接口），或外购"电动云台 PTZ 支架"改用外部步进电机驱动其内部减速结构
- 旋转轴：同理，优先找带内置减速机构的成品旋转平台，而不是从零加工减速箱
- 3D 打印件只负责"成品云台 ↔ 滑轨转接板"和"成品云台 ↔ FL-20G 镜筒抱箍"这两处适配件，这部分沿用现有 `04_slider_adapter_plate.stl` 思路即可，不需要你自己解算蜗轮蜗杆参数

**决策点 D1**：是否接受"外购成品云台底座+自制适配件"的方案（我可以在下一步选型阶段找到具体可买到的云台产品并核算扭矩是否够扛下 FS-300B+FL-20G 的重量），还是坚持自制减速结构（风险更高、需要更长调试周期）？

### A2 · 增加回零与限位保护

- 滑轨、俯仰轴、旋转轴各自加装两个限位开关（清单里已经买了3个 EE-SX672，够用但建议滑轨单独配一对，云台俯仰/旋转合用现有数量需要重新核算，具体见 B1 清单合并部分）
- ESPHome 层面加入标准 homing 流程：上电后先低速反向运动直到触发限位开关，将该点标定为坐标原点，再进行正常的 `stepper.set_target` 控制，替代现有"回零=直接把 number 设为0"的伪回零
- 行程两端各设置一个软件极限位（略小于机械限位触发点），双重保护

### A3 · 急停按钮接入

- 蘑菇头急停按钮接一路 GPIO 输入（建议独立于两块 ESP32 各接一路，或做成硬件串联在 24V 电源总输出上，直接切断电机驱动电源），触发时立即调用 `stepper` 的急停/切电机使能，而不是仅停留在软件 switch 层面
- 这属于新增电路设计，建议做成"总电源硬件互锁"（急停按钮直接串在 24V 主电源正极回路里），比纯软件方案更可靠

### A4 · FS-300B 控制协议重新验证

在正式写死协议帧之前，先做验证再动手，避免在你已经组装完机械结构后才发现灯控不上：

1. 用 nRF Connect（安卓/iOS 免费 App）扫描并连接 FS-300B，抓取实际的 Service/Characteristic UUID，和脚本里的 `0xFEE0/FEE1/FEE2` 核对是否一致
2. 如果 GitHub 的 nanlite-reverse-engineering 项目本身有更新或 issue 讨论真实协议帧格式，以那边的最新结论为准，而不是直接照抄现在这份脚本里的常量
3. 过渡方案（README 里已经提到，建议保留为 P0 兜底）：先用华为智选插座控制电源通断 + NANLINK App 里预设一次亮度色温（灯有断电记忆），协议没抓通之前，先靠这个方案让四个场景至少能跑起来，蓝牙精细调光作为 P1 增强

**决策点 D2**：蓝牙协议验证工作量未知（可能几小时也可能需要多次抓包调试），是否接受先用"插座通断+断电记忆"作为过渡方案上线，蓝牙调光作为后续迭代？

### A5 · 施工纲要补充"自己动手 vs 找工人"标注

| 工序 | 归属 | 理由 |
|---|---|---|
| 3.5m 滑轨顶棚固定（膨胀螺栓打孔） | **建议找工人确认后自己动手，或找工人打孔** | 涉及结构承重开洞，且实际悬挂重量需要重新核算（见 B4），如果重新核算后总重超过 15kg，建议直接找工人施工这一步 |
| 24V 开关电源接市电 | **自己动手**，但需先确认现有插座回路的额定电流是否够（350W 灯 + 其他负载） | 不涉及改动房屋固定线路，是设备端接线，普通人可操作 |
| ESP32/驱动板等弱电接线、ESPHome 刷写 | 自己动手 | 全部是低压弱电，无资质要求 |
| 3D 打印件组装、云台适配件安装 | 自己动手 | 机械组装，无特殊风险 |
| 拖链/坦克链走线布置 | 自己动手 | 常规布线工作 |

## 四、B 级问题的优化建议

### B1 · 合并采购清单为一份权威版

以`采购清单_最终完整版.md`为基础（功能更全），但需要你确认：
- 步进电机到底要3台还是4台（原始 README 说3台：滑轨1+云台2，完整版清单写4台但未说明第4台用途——如果是备用件可以保留，但要在清单里注明"备用"）
- 限位开关数量按 A2 方案重新核算：滑轨2个（两端）+俯仰轴2个+旋转轴2个，共6个，而非现有的3个

### B2 · 补全已采购但未接入代码的硬件

| 硬件 | 建议用途 |
|---|---|
| 限位开关×6 | 见 A2 |
| 温度传感器 DS18B20×3 | 分别测 TMC2209 驱动板、24V电源、FS-300B 灯体附近温度，超温报警并联动降功率或断电，写入 HA |
| 光照传感器 BH1750 | 用于双钥匙模式：室内已经足够亮时，App 触发场景仅移动机械位置但不开灯，或自动降低目标亮度 |
| mmWave 人体存在传感器 | 双钥匙模式：无人时定时自动关闭系统（比如场景开启后30分钟检测不到人体则关闭），避免忘关空跑 |
| OLED 显示屏 | 显示当前场景/滑轨位置/云台角度，本地状态一目了然，不依赖手机 |
| EC11 编码器 | 本地手动微调当前场景的位置/角度，不用每次都进 App |

这几项不是必须做，但既然已经买了，建议至少纳入这次的施工阶段代码里，否则等于白买。

**决策点 D3**：B2 里这几项传感器联动逻辑，是这次施工阶段就一起做，还是先跑通四个基础场景，这些作为后续迭代？

### B3 · 双钥匙模式落地

结合 B2 的传感器，在 `ha_automations.yaml` 里补充：
- 场景触发时先读 BH1750，若环境亮度已经超过阈值（比如书桌场景环境已经很亮），跳过开灯或降低目标亮度
- mmWave 检测无人持续 N 分钟后自动触发"全局关闭"

### B4 · 重量与扭矩核算

在下一步选型阶段，我会：
1. 核实 3.5m 型材导轨的实际线密度（按具体选定的时代超群 DS45P 型号查规格书）
2. 核实 FS-300B（约2-3kg）+ FL-20G（镜筒直径200mm，估计1-1.5kg）+ 云台组件的合计重量
3. 反推需要的步进电机扭矩/推力，核对现有 57BYG 电机选型是否够用
4. 根据核算后的总重量，重新确认膨胀螺栓规格和固定点数量

### B5 · 补全四个场景的定时触发

在 `ha_automations.yaml` 里给场景2/3/4 也加上 `time` trigger，对齐采购清单里标注的 9:00/10:00/19:00，与场景1保持一致的触发结构。

### B6 · HA 主机选型

斐讯N1（S905D/2GB）跑基础 HA 场景没问题，但考虑到 0211 全屋中枢未来会汇聚其他所有智能模块的数据，2GB 内存长期看大概率不够用。

**决策点 D4**：
- 选项A：现在直接上树莓派5 8GB（¥400-500，比清单贵约¥350-400，但为 0211 中枢留足性能余量）
- 选项B：先用斐讯N1（¥90）跑通 0201，等 0211 中枢要做的时候再评估升级，多花一次搬迁配置的功夫但先省钱

## 六、决策结果（2026-09-03 已拍板）

| 决策点 | 结果 |
|---|---|
| D1 云台机械结构 | **外购成品云台底座 + 自制转接件**。⚠️ WebSearch 复核发现：搜索引擎能查到的多是消费级摄影/直播云台（自带闭环控制，不开放步进电机接口，承重通常≤3kg），没有确认到能直接买、开放步进接口、承重够扛 FS-300B+FL-20G 组合的成品。**这一项的具体选型需要放到专门的"阶段2 设备电商平台选型"对话里、在淘宝App内用更细关键词多轮搜索确认**，本次评审不再勉强给出不确定的链接。 |
| D2 FS-300B 灯控 | **插座通断 + App 断电记忆过渡上线**，蓝牙精细调光作为 P2 后续增强，本次施工阶段不依赖 `fs300b_control.py`。 |
| D3 传感器联动 | **本阶段不做**，先跑通4个基础场景（纯手动+定时触发），已购的温度/光照/人体存在等传感器留到后续迭代对话里再接入代码。 |
| D4 HA 主机 | **树莓派5 8GB**，替换采购清单里的斐讯N1，为 0211 全屋中枢预留性能余量。 |

以上决策已同步落实到本次更新的配置文件里（见下方"七、本次已更新的技术文件"），A2/A3/A5（限位回零、急停接入、施工工序标注）已在配置和本文档里落实；A1（云台结构选型）、A4（蓝牙协议验证）留待后续对话推进。
